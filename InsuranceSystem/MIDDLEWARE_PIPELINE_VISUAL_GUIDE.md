## Why ASP.NET Core Middleware Order Matters

Middleware works like a **pipeline** - each layer processes the request in order:

```
        Request comes in
            ?
    ?????????????????????
    ? Middleware 1      ?  ? Processes first
    ?????????????????????
            ?
    ?????????????????????
    ? Middleware 2      ?  ? Processes second
    ?????????????????????
            ?
    ?????????????????????
    ? Middleware 3      ?  ? Processes third
    ?????????????????????
            ?
    ?????????????????????
    ? Endpoint Handler  ?  ? Finally executes
    ?????????????????????
            ?
        Response sent back
```

### If CORS is late in pipeline:
```
Request ? CORS check happens ? ? Fails ? Request blocked ? 401 Error
```

### If CORS is early in pipeline:
```
Request ? ? CORS allows it ? Auth validates ? ? Authorization checks ? Success ? 200 OK
```

## Related Concepts

### 1. CORS Preflight Requests
```
Browser automatically sends:
  OPTIONS /api/resource
  (asking: "Am I allowed to make requests from this origin?")

Server must respond:
  ? 200 OK with CORS headers
  ? Before checking auth/authz

If CORS fails ? Browser blocks request ? 401 (or CORS error)
```

### 2. Bearer Token Flow
```
Client (Browser)                    Server (API)
    ?                                   ?
    ?? Login with credentials ????????? ?
    ?                                   ? Generate JWT
    ? ? Token (JWT) ???????????????????
    ?                                   ?
    ?? Protected Request ??????????????? ?
    ? Headers:                          ?
    ? Authorization: Bearer {token}     ?
    ?                                   ? Validate token
    ?                                   ? Check role claim
    ? ? 200 OK (with data) ????????????
    ?                                   ?
```

### 3. Role-Based Authorization
```
Token contains:
  {
    "sub": "1",
    "role": "Customer",  ? This claim is checked
    "nameid": "1"
  }

Endpoint requires:
  [Authorize(Roles = "Customer")]  ? Must match exactly
```

## Quick Reference: Middleware Order

```csharp
// ? CORRECT ORDER
app.UseHttpsRedirection();
app.UseCors("AllowAngularFrontend");   // ? CORS FIRST (before routing)
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

// ? INCORRECT ORDER (causes 401)
app.UseHttpsRedirection();
app.UseRouting();
app.UseCors("AllowAngularFrontend");   // ? CORS AFTER routing (wrong!)
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
```
